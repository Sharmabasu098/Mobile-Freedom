# M12.1 — Storage Snapshot Data Model

**Status:** Implementation started — isolated branch  
**Branch:** `m12.1-storage-snapshot-model`  
**Scope:** Data structure and fail-closed validation only.

## Safety boundaries
- This model represents explicitly supplied measurements; it does not claim continuous device monitoring.
- Byte fields must be non-negative safe integers.
- Total storage must equal used + free storage.
- Snapshot identifiers and timestamps are required.
- Data provenance is recorded as `user-provided` or `browser-derived`.
- No trend calculations, warnings, prediction, persistence, or UI are included in M12.1.

## Acceptance checks
- Valid, internally consistent snapshot is accepted.
- Empty identifier and invalid timestamp are rejected.
- Negative, fractional, or unsafe byte values are rejected.
- Contradictory storage values are rejected.
- Unknown provenance is rejected.
- Tests and typecheck must run before this sub-milestone is considered verified.
