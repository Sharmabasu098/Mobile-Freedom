# VF-02.5 — Persistent Memory Storage (Test-First Scope)

**Status:** IN PROGRESS — scope and test matrix proposal  
**Base:** VF-02.4.4 merge commit `226636abed43c92798f01a6c47076818b453cd66`  
**Workflow:** Test-first, isolated branch; `main` must remain untouched.

## Goal
Add an explicit, privacy-conscious persistence layer for user-approved memory candidates. This milestone must not silently persist extracted candidates or expand the extraction scope from VF-02.4.x.

## Scope boundaries
- Persistence is separate from extraction; `extractMemoryCandidates()` remains pure.
- Only explicit user-approved/opted-in candidates can be persisted.
- Existing candidate safety filters remain in force; persistence must revalidate sensitive-data boundaries.
- Memory records need stable identifiers, timestamps, and a schema version (exact model to be defined by tests).
- Provide deterministic retrieval/listing and user-requested deletion of stored records.
- Storage errors, malformed stored data, and unavailable storage must be handled without crashing the app or silently claiming a write succeeded.
- Storage backend/API is not locked in this scope proposal; choose after inspecting the current app constraints and tests.
- No automatic file deletion, no background extraction, no external sync, no account/cloud storage, and no changes to locked architecture.
- Do not store secrets or sensitive personal data. User control and clear failure states are required.

## Proposed Acceptance Criteria (AC)
1. **AC-01 Opt-in boundary:** no persistent write occurs unless the user explicitly opts in / approves the candidate.
2. **AC-02 Approved save:** approved, safe candidates are stored and returned with stable record identity and required metadata.
3. **AC-03 Persistence across reload:** records survive application reload when the selected storage backend supports persistence.
4. **AC-04 Retrieval:** stored records can be listed/retrieved deterministically; no unrelated records leak into the result.
5. **AC-05 Duplicate handling:** saving the same candidate does not create uncontrolled duplicates; behavior is deterministic and tested.
6. **AC-06 Update semantics:** updating a candidate replaces/updates the intended record without corrupting other records.
7. **AC-07 Delete control:** user-requested deletion removes the selected stored memory; unrelated memories remain intact.
8. **AC-08 Storage-boundary safety:** sensitive or unsafe candidates are rejected even if they reach the persistence API.
9. **AC-09 Extraction-only separation:** pure extraction and preview operations have no storage side effects.
10. **AC-10 Corrupt-data resilience:** malformed or unknown-version persisted data is handled safely, with no crash or silent destructive rewrite.
11. **AC-11 Storage failure:** quota/unavailable/read/write failures are surfaced safely; no false success and no partial record corruption.
12. **AC-12 Schema/version compatibility:** schema version is explicit and compatibility behavior is covered (supported version read; unsupported version safely handled).

## Proposed Test Matrix (tests first; implementation not started)
| ID | Scenario | Expected |
|---|---|---|
| PM-01 | No opt-in/approval | No write; stored set unchanged |
| PM-02 | Explicitly approved safe candidate | Record saved with stable ID and metadata |
| PM-03 | Reload/reinitialize storage | Previously saved record remains available |
| PM-04 | Retrieval/listing | Deterministic records; no unrelated entries |
| PM-05 | Save duplicate candidate twice | Defined duplicate policy; no uncontrolled duplicates |
| PM-06 | Update selected record | Target updated; other records unchanged |
| PM-07 | Delete one record | Target removed; other records retained |
| PM-08 | Sensitive candidate sent directly to storage API | Rejected; no write |
| PM-09 | Extraction/preview path | No persistence side effects |
| PM-10 | Malformed JSON/record or unknown schema version | Safe error/empty-safe result; no crash or destructive rewrite |
| PM-11 | Storage unavailable, quota, read/write failure | Safe surfaced error; no false success; existing data protected |
| PM-12 | Supported/unsupported schema versions | Supported data loads; unsupported version is handled safely |
