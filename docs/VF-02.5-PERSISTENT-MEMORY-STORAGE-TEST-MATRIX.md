# VF-02.5 — Persistent Memory Storage (Test-First Scope)

**Status:** AC LOCKED — tests-first phase
**Base:** VF-02.4.4 merge commit `226636abed43c92798f01a6c47076818b453cd66`
**Branch:** `vf-02.5-persistent-memory-storage-test-first`
**Safety:** isolated branch; `main` untouched.

## Goal
Add an explicit, privacy-conscious persistence layer for user-approved memory candidates without changing VF-02.4.x extraction behavior.

## Locked scope boundaries
- Persistence is separate from extraction; `extractMemoryCandidates()` remains pure.
- Only explicitly approved candidates may be persisted.
- Storage API revalidates candidate safety; sensitive data is rejected regardless of approval.
- Stored records include stable ID, category/value, created/updated timestamps, and schema version.
- Deterministic retrieval/listing and targeted update/delete are supported.
- Storage errors are surfaced; no false-success writes, crash, partial corruption, or silent destructive reset.
- No auto file deletion, background extraction, external sync, account/cloud storage, or architecture change.
- Storage is accessed through an injectable adapter to keep tests deterministic and avoid requiring browser globals.
- Duplicate policy: same category + normalized value (trim, collapse whitespace, case-insensitive) maps to one record; repeated save is idempotent.
- Update preserves record identity and createdAt while changing value/updatedAt; unrelated records remain unchanged.
- Schema version is 1. Unknown versions/malformed data are surfaced safely and the original persisted bytes are not overwritten automatically.
- User-facing approval is represented by an explicit approval argument at the storage boundary.

## Locked Acceptance Criteria
1. **AC-01 Opt-in:** no write without explicit approval.
2. **AC-02 Approved save:** safe approved candidate saves with stable ID and metadata.
3. **AC-03 Reload persistence:** saved records survive store re-instantiation using the same adapter.
4. **AC-04 Retrieval:** listing is deterministic and contains only stored records.
5. **AC-05 Duplicates:** same category + normalized value is idempotent.
6. **AC-06 Update:** target identity and createdAt are preserved; updatedAt/value change; unrelated records are unchanged.
7. **AC-07 Delete:** only selected record is deleted.
8. **AC-08 Safety:** sensitive candidates are rejected at storage boundary, even when approved.
9. **AC-09 Extraction separation:** extraction/preview never writes to persistence.
10. **AC-10 Corrupt data:** malformed/unknown-version data produces a safe surfaced error; no crash or silent rewrite.
11. **AC-11 Failure safety:** adapter read/write/quota failures surface as errors; existing persisted data is protected; no false success.
12. **AC-12 Versioning:** schema version 1 reads; unsupported versions safely error without rewriting original data.
