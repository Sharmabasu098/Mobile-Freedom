# M12.3 — Storage Trend Analysis

**Status:** Implementation in progress — isolated branch  
**Scope:** Locked  
**Branch:** `m12.3-storage-trend-analysis`

## Implementation (initial)

- Pure trend-analysis function using explicitly supplied validated M12.1 snapshots.
- AC-01 integration helper retrieves history through the M12.2 store interface (`getHistory`), then passes returned snapshots to the pure analyzer. Persistence remains encapsulated by M12.2.
- Requires at least two snapshots.
- Rejects invalid snapshots and duplicate IDs.
- Sorts by timestamp, with ID tie-break for equal timestamps.
- Compares earliest and latest snapshots for used, free, and total bytes.
- Reports direction based on used bytes: increase, decrease, unchanged.
- Calculates used-byte change per day only when elapsed time is positive.
- Same-timestamp snapshots may be compared, but no rate is emitted.
- No monitoring, filesystem scanning, file mutation, deletion, or prediction.

## Tests

Focused unit tests cover AC-01 M12.2 history retrieval, insufficient history, history-read failure propagation, increase, decrease, unchanged usage, timestamp ordering, invalid snapshots, duplicate IDs, zero-duration comparisons, zero-capacity and zero-usage transitions, maximum-safe-integer boundary values, thrown M12.2 history-read exceptions, and deterministic output.
