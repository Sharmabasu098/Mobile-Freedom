# M11.2 — Context & Safety Guards

**Status:** IN PROGRESS — isolated implementation

## Purpose
Validate context before Storage Assistant insights are generated. The guard is fail-closed: malformed facts are rejected rather than treated as trusted.

## Covered checks
- File count, total bytes, duplicate group count, and potential savings must be finite/non-negative and have valid integer constraints where applicable.
- Large-file entries must have a name and a finite, non-negative size.
- A completed similar-photo scan must provide a valid non-negative pair count.
- A pair count cannot be supplied when the similar-photo scan is not marked complete.
- Display filenames are stripped of control characters and length-bounded.

## Safety boundary
This validator does not scan files, access device-wide storage, upload data, delete files, or invoke a remote model. It only validates supplied context.

## Verification required before PASS
- Unit tests pass.
- TypeScript and production build pass.
- Guard is wired into the assistant entry path (not merely present as an unused helper).
- Invalid context prevents insight generation or produces a clear unavailable response.
- Regression checks for M11.1 outputs remain passing.
- CI and review pass.

M11.2 is not PASS until integrated and verified.
