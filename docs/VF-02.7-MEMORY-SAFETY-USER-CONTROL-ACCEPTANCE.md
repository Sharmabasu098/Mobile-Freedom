## Goal
Give the user understandable, explicit control over persistent memory. Memory must remain privacy-conscious and user-directed.

## Locked scope for VF-02.7
- Privacy and sensitive-data safeguards
- Explicit permission boundaries for saving or changing persistent memory
- Memory pause/resume control
- User-visible memory review/listing
- Correction/update of a selected memory
- Deletion of a selected memory and delete-all memory control
- Retention behavior and expiry policy
- Safe behavior when storage is malformed, unavailable, or controls are paused
- Regression coverage for VF-02.5 storage and VF-02.6 retrieval

## Acceptance criteria
- **MSU-01 Permission:** no memory is persisted without explicit, affirmative approval.
- **MSU-02 Sensitive-data safety:** sensitive candidates are rejected; no sensitive data is automatically persisted.
- **MSU-03 Pause:** when memory is paused, automatic extraction/save is disabled; existing records are not silently deleted.
- **MSU-04 Resume:** resuming restores allowed behavior without retroactively saving candidates captured while paused.
- **MSU-05 Review:** user can inspect the stored records and metadata needed to identify each record.
- **MSU-06 Correction:** correcting a record updates only the selected record; invalid and duplicate updates are rejected safely.
- **MSU-07 Delete one:** deletion affects only the selected record and is verifiable.
- **MSU-08 Delete all:** explicit confirmation is required; after confirmation no persistent records remain.
- **MSU-09 Retention:** expiry is deterministic, configurable/policy-based, and documented; records beyond retention are excluded or removed according to approved behavior. No silent indefinite retention.
- **MSU-10 Fail-safe:** storage errors or malformed state do not silently bypass privacy controls or claim a successful action.
- **MSU-11 Retrieval boundary:** pause/control state must prevent retrieval when disabled; resuming does not revive deleted records.
- **MSU-12 Regression:** VF-02.5 persistent storage and VF-02.6 retrieval behavior remains covered and passes.
- **MSU-13 Verification:** focused tests, TypeScript check, production build, diff review, and exact commit SHA are required before PASS.
- **MSU-14 No scope drift:** no main changes, no merge, and no unrelated milestone changes during this milestone.

## Explicit non-goals
- No new memory categories without approval.
- No automatic deletion of unrelated application files.
- No external/cloud memory sync.
- No new AI model/provider dependency.
- No change to VF-02.6 relevance scoring unless a safety defect is demonstrated and separately reviewed.
