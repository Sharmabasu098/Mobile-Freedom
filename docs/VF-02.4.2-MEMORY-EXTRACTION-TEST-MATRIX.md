## Negative / false-positive regression group

These must **not** produce durable memory candidates:
- A joke, sarcasm, or casual reaction without durable meaning.
- A one-time command or request.
- Temporary status with a time-bound signal (e.g. today/now/this week).
- A hypothetical, fictional, role-play, or example statement.
- A quote or statement clearly attributed to another person.
- An ambiguous statement with no reliable subject or scope.
- Sensitive information unless explicitly authorized through a permitted memory workflow.
- A topic the user asked not to remember.

## Acceptance criteria

1. Every critical case has an executable assertion in the implementation phase.
2. False-positive/negative tests must be included; positive extraction tests alone are insufficient.
3. Extraction preserves meaning, category, subject, and scope.
4. Temporary, hypothetical, quoted, ambiguous, and sensitive inputs are safely rejected or handled according to explicit policy.
5. Duplicate candidates are deduplicated.
6. Contradictions and context-specific updates are handled deterministically and tested.
7. English, Hindi, and Hinglish coverage is present.
8. VF-02.1 and VF-02.2 regression tests continue to pass.
9. No production implementation changes are included in this test-matrix PR.
10. PR is not merged until this matrix is reviewed and the later implementation PR passes CI and regression verification.

## Executable test contract (locked for first implementation)

The first test file assumes this exported API:

- `extractMemoryCandidates(input: string)` returns an array of candidates.
- Candidate fields asserted by tests: `category` (preference/project/instruction), `durable` (boolean where applicable), and `value` (meaningful extracted text).
- Safety-rejected or insufficient-evidence inputs return an empty array.
- Tests are contract-first and currently expected to fail while the module/API is absent. This expected red state is not a PASS and must not be merged.
